# 保留历史并修复解密错误

## 适用与版本边界

用于后端明确返回 invalid_encrypted_content，且错误指向历史 item 的情形。仅出现加密字段或代理自述“看不到正文”时，先按诊断流程排查。

本方法在 2026-11-14、应用 26.1106.51428、自带 CLI 0.167.0-alpha.4.1 完成真实验证。尤其 thread/revert、beforeTurnId、deferGoalContinuation、attachToSource 的可用性及互斥条件，必须以当前安装版本 schema 为准。

## 建立可审查的边界

1. 确认目标 ID、归档状态、provider、模型、审批设置和是否有正在运行的 turn。
2. 将报错 item 映射到准确 turn。保留完整错误码和时间，不输出密文；通过分页读取核对前后顺序，遍历必要页而非只看最近一页。
3. 列出该 turn 及之后将移除的所有轮次：成功业务、失败、中断、测试和尚未处理的输入。保留重要明文业务事实与产物位置，不把无法解密的内容猜写成已恢复。
4. 说明历史回退不会撤销本地文件、Git、数据库或远程副作用。若回退会丢失已有授权未覆盖的成功业务历史，先将具体边界交用户决定。已选定且有授权的修复范围直接推进。

## 核验快照后操作

使用正式工具或同版本 thread/fork 保存完整原历史。记录快照 UUID，分页核对所有原 turn ID、顺序与数量。快照创建失败或核验不完整时，不执行回退。

核对源会话 goal 和 fork 自动续跑行为。当前版本支持 deferGoalContinuation 时可用它抑制自动继续；不支持且不能保证静默快照时，暂停该操作。不要把它与互斥的 attachToSource 参数一起使用。保存快照后可按授权归档，避免混入业务执行。

再次核对源历史和运行状态未漂移。通过正式 thread/revert 指定 beforeTurnId；该 turn 和后续全部排除。保留目标 chat ID，回读实际保留的历史前缀，必须与计划完全一致。发现新业务 turn 或不明差异，停止并重新评估边界。

## 运行时占用及 app-server

优先使用宿主现有会话工具。缺少所需方法时，可使用应用自带、版本已核实的 app-server；沿当前 CLI 帮助确定启动参数，不能仅凭 PATH 中同名 codex 判断兼容。

- JSONL 协议先 initialize，等待成功，再发送 initialized。请求 ID 唯一，所用实验字段按 schema 启用能力。设置单请求超时，记录响应，不把握手通知当作操作完成。
- thread/read 可从持久记录读到目标，但当前版本的 thread/revert 要求该运行时已加载目标。返回 thread not found 时，先核实 ID 和版本，再 thread/resume；不能将它误判为聊天已被删除。
- resume 返回 already has an active writer 时，停止该尝试。通过拥有者的正式能力释放目标占用。运行中目标先协调到安全停点，不强制终止其他任务。
- 本次实测：对空闲/报错的目标，正式 archive 释放桌面占用；再 unarchive、resume、revert；最后恢复目标原归档状态。每一步均核对成功和状态。失败时保留快照，恢复原可见状态，报告未完成步骤。
- 不删锁，不杀宿主，不改数据库状态，不使用标注 DO NOT USE 的 history 覆盖参数代替正式修复。只退出本任务启动的辅助进程。

如首次测试又返回另一个损坏 item，停止自动扩展回退；重新定位并核对历史损失。保留既有快照和失败证据，不能循环向首轮回退。

## 验证后的业务续接

用技能入口的两轮标记合同验证。核对 provider、模型、审批和原可见状态。跨 chat 测试须记录真实来源与目标；原生子代理要用自己的 spawn/follow-up 通道验证。

恢复 chat 不代表原业务登记器支持所有权迁移。核对正式接管入口、当前唯一执行者和可恢复检查点；不伪装旧 CODEX_THREAD_ID、不手改 registry、不并发恢复历史部署。

## 已验证案例的范围

一次从旧子代理 fork 的恢复会话继承了无法解密的消息。原调用在 provider 改变后返回 invalid_encrypted_content；两次旧通信验证不能证明新 provider 下续聊可用。

修复先核验八轮历史的完整快照，再回退第一条损坏消息所属 turn。尾部六轮包含三次中断、两轮测试和一次失败续聊；前两轮工作记录保留。受支持的 revert 后，同一 chat 完成两轮精确回复，第二轮验证了持久化历史后的续聊，用户随后明确验收。此结果不证明密文已被解密，也不证明所有旧代理已恢复。
