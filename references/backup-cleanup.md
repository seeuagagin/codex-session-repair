# 验收后清理本次备份

## 范围与依据

核对本次真实用户验收、清理授权、修复记录和资源身份。修复通过不自动授权永久删除快照；用户已明确要求“验证通过，清理这次修复备份”时，按已登记范围继续，不重复索要相同许可。宿主删除工具自身的审批要求仍须满足。

清理前先保留必要的脱敏材料：修复摘要、原/恢复会话映射、回退边界、接口结果、验证证据、用户验收及经验结论。将需要保留的审计材料放到本次删除目录之外；不保留无用途的完整历史副本冒充清理。

## 快照只按精确 UUID 删除

1. 从原修复记录取得快照 UUID，通过正式列表核对 host、归档状态和目标身份，排除当前及恢复 chat。同标题不能证明同一对象。
2. 检查 spawned descendants 和 attached side chats 的递归删除范围。出现未获授权的关联会话时，暂停该快照删除并列出具体级联范围。
3. 优先使用正式 delete_thread 工具。按工具约定提供来自列表的 ID，并尊重审批或锁。缺少工具时，按当前版本的 [thread/delete 文档](https://learn.chatgpt.com/docs/app-server#delete-a-thread)核对正式 CLI 接口；不通过直删数据库、日志、锁或换入口绕过拒绝。
4. 接口成功后核验精确 UUID 的记录与对应 rollout 文件已消失，正式列表无该 ID。需 SQLite 辅助核验时用 mode=ro。确认恢复 chat 仍存在且可读取，不以同标题匹配数量作为删除依据。
5. 列表仍有该 UUID 时，优先正式刷新。没有现场 schema 和安全停机条件时，不手改运行中的全局状态或列表缓存。分别报告内容与显示残留。

## 文件与临时资源

按修复登记的精确路径冻结清单，包括备份目录、协议输出、专用脚本和指针文件。记录属主、类型、设备/inode、文件数量及逻辑字节；核对指针真实指向、路径归属、软链接、活动写入和必要依赖。缺少身份或内容漂移时暂停对应对象，不用临时文件名前缀做全局删除。

删除前复查身份与范围未变。只递归删除已确认专属于本次修复的目录，不跟随软链接；删除后逐路径核对不存在。共享资源、正式会话、配置、业务产物和审计证据排除在外。失败立即停止后续受影响操作，留存部分回执，不盲目重跑。

清理前后记录同一存储的可用字节及观测差值，另记可归属的逻辑删除量。并发活动和共享存储可能使空间差值为负；未知物理释放量就写未知，不用逻辑文件大小相加冒充释放空间。

## 完成标准与实测边界

回执分别记录快照删除数、级联数、路径/文件数、保留项、失败、未验证项和恢复 chat 状态。使用真实用户验收时间，保留证据链接；没有绑定 Issue 时不猜测项目或发布目标。

2026-11-14 实测：通过正式删除工具删除一个归档快照，无级联；数据库与日志复核为空。清理八个精确路径、539 个文件、5,034,021 个逻辑字节；保留报告、映射和验证证据。恢复 chat 保持同一 ID，读取时 idle，最后验证轮完成且无错误。这些数量仅描述该次案例，今后按实际清单计算。
